# Block Expressions

In programming language syntax, syntactic forms are split into those that are expressions and those that are statements. Expressions evaluate into a value, while statements do not. As a general rule, imperative languages such as C, Java, C++, etc. have many statements, while functional languages such has Haskell, OCaml, or Lisp, have mostly expressions.

As an example, let's take an `if` syntactic form. In Java and C, an `if` is a statement:

```java
if (a.equals(b)) {
  message = "equal";
} else {
  message = "not equal";
}
```

Contrast this to OCaml, where `if` is an expression:

```ocaml
let message = if a = b then "equal" else "not equal"
```

Because `if` in OCaml is an expression, it can be assigned to `message` directly. This is both more concise, and also avoids having message be a mutable variable. Indeed, this is a sufficiently useful pattern that most imperative languages also include an expression based `if` in the form of a ternary operator `?`:

```c
char* message = a == b ? "equal" : "not equal"
```

However, ternaries have limitations. The branches cannot be more than a single expression, and nesting them is rather difficult to read.

To solve this, we can use *block* expressions. Block expressions can contain multiple statements and a final expression that becomes the value of that block.

```rust
let student = {
    let school = School::from("Stony Brook");
    let gpa = 4.2;
    let name = "Jorge";
    
    Student {
        name,
        gpa,
        school
    }
}
```

With block expressions, we can have an `if` that executes multiple statements and returns a single value:

```rust
let bio = if student.is_grad_student() {
    let thesis = student.thesis();
    let department = student.department();
    
    format!("is studying {} in the {} department", thesis, department)
} else {
    format!("is an undergraduate")
}
```

However, blocks in Rust don't have to be expressions. They can also be statements:

```rust
{
    let student = db.get_student()?;
    student.enroll();
}
```

And so can `if`s:

```rust
if student.is_graduating() {
    println!("congrats!");
} else {
    println!("keep studying")
}
```

It's fitting that a language which inherits from both imperative and functional languages has syntactic constructs that can behave as both statements and expressions.
